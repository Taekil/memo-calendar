# 메모 달력 스킬

사용자가 혼자 쓰는 바탕화면 메모 달력의 데이터 파일 `memos.json`을 Claude가 직접 읽고 고친다.
앱에는 AI가 없다. 요약·추가·완료·삭제는 모두 이 스킬이 파일을 다루는 방식으로 한다.

## 가장 중요한 원칙

- 이 앱의 핵심은 **날짜 칸에 아무 문장이나 자유롭게 적는 것**이다. 메모 문장을 구조화하거나 다듬거나 다시 쓰지 않는다. 사용자가 말한 표현을 그대로 넣는다.
- 읽기·요약은 바로 한다. **쓰기(추가·완료·수정·삭제)는 변경 목록을 먼저 보여 주고 확인받은 뒤** 한다.
- **삭제는 사용자가 명시한 메모만** 한다.
- 쓰기 직전에 반드시 백업을 만든다.

## 데이터 위치

- 이 PC(Claude Code): `%OneDriveCommercial%\memo-calendar\memos.json` (OneDriveCommercial이 비어 있으면 `%OneDrive%\memo-calendar`). 백업 폴더는 같은 폴더의 `backup`.
- 휴대폰·웹(파일 시스템 없음): Microsoft 365 연결의 SharePoint 도구로 같은 파일을 쓴다. 개인 OneDrive 경로(자신의 주소로 바꿀 것) `https://<조직>-my.sharepoint.com/personal/<계정>/Documents/memo-calendar/memos.json`. `sharepoint_search`로 파일 이름 `memos.json`을 찾고, 본체가 안 잡히면 `sharepoint_folder_search`로 `memo-calendar` 폴더를 찾아 `read_resource`로 폴더 내용을 확인한다. 읽기는 `read_resource`, 쓰기는 `sharepoint_update_file`, 백업은 `sharepoint_upload_file`(backup 폴더)을 쓴다.
- 어느 쪽 도구가 있는지 보고 가능한 쪽을 고른다. 둘 다 안 되면 그 사실을 사용자에게 말하고 멈춘다. 추측으로 다른 파일을 만들지 않는다.

## 파일 형식

```json
{"memos":[{"id":"mvt6k4e5e46hv","date":"2026-10-07","text":"메모 내용","task":false,"done":false,"updated":"2026-10-29T06:46:38.141Z"}]}
```

- `date`: `YYYY-MM-DD`. 메모 한 줄 = 항목 하나. 한 날짜에 여러 항목이 있을 수 있고 **같은 날짜 안의 순서가 화면 표시 순서**다.
- `task`/`done`: 앱은 더 이상 `[ ]`·`[x]` 표시를 쓰지 않는다. 새 항목은 둘 다 false로 넣고, 기존 항목의 값은 그대로 둔다. "완료 표시" 요청이 오면 상태를 바꾸지 말고 메모 문장을 고치거나 삭제할지 묻는다.
- `updated`: UTC ISO 시각 `2026-11-04T02:16:07.000Z` 형식. **바꾼 항목만** 갱신한다.
- `id`: 기존 항목은 그대로 유지한다(중복 방지 키). 새 항목은 밀리초 시각을 36진수로 바꾼 값 + 임의 영숫자 6자.
- 저장은 UTF-8(BOM 없음), 앱과 같은 한 줄 압축 JSON(`separators=(',',':')`, `ensure_ascii=False`). 전체 목록을 날짜순으로 정렬하되 같은 날짜 안의 상대 순서는 유지(안정 정렬)한다.

## 요약 (읽기 전용)

1. 파일을 읽고 요청한 기간만 추린다. 주 단위는 **일요일~토요일**(달력과 같은 기준). "지난주"="오늘 기준 직전 일~토", "이번 주", "지난달", "이번 달" 모두 오늘 날짜로 계산한다.
2. 날짜 순으로 읽고 **주제별로 묶어 짧게** 정리한다. 메모 문장에 진행 중/완료/보류 같은 말이 있으면 그대로 구분한다. 메모에 없는 내용을 지어내지 않는다.
3. 빈 날짜, 메모가 하나도 없는 기간이면 그렇다고 말한다.

## 추가·완료·수정·삭제 (쓰기)

1. 파일을 읽고 변경 대상을 찾는다. 대상이 둘 이상으로 애매하면 어느 것인지 묻는다.
2. **변경 목록**(추가/완료/수정/삭제 각각, 날짜와 문장)을 보여 주고 확인을 받는다. 날짜를 "내일" 같은 말로 받았으면 계산한 실제 날짜를 같이 적는다.
3. 확인되면 백업을 만든다: `backup` 폴더에 `memos_YYYYMMDD_HHMMSS_<사유>.json`으로 현재 파일을 그대로 복사(또는 업로드).
4. 위 형식 규칙대로 저장한다. 저장 후 파일을 다시 읽어 항목 수와 바뀐 항목을 확인한다(추가 +n, 삭제 -n이 맞는지).
5. 결과를 한두 줄로 보고한다. 앱은 파일이 바뀌면 자동으로 다시 읽는다.

## 하지 않는 것

- 사용자가 요청하지 않은 항목을 고치거나 지우지 않는다.
- 메모 문장을 요약해서 덮어쓰지 않는다(요약은 답변으로만 한다).
- 파일이 읽히지 않거나 JSON이 깨졌으면 **저장하지 않고** 사용자에게 알린다(백업 폴더의 최근 파일을 안내).
