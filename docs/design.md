# 설계

## 원칙

1. **자유 입력이 핵심입니다.** 날짜 칸에 아무 문장이나 적는 것이 이 앱의 가치입니다. 할 일 표시, 분류, 반복 일정처럼 구조를 강요하는 기능은 넣지 않습니다. (예전에 있던 `[ ]`/`[x]` 할 일 표시도 뺐습니다. 지금 입력창의 규칙은 "한 줄 = 메모 하나"가 전부입니다.)
2. **앱에는 AI가 없습니다.** 요약이나 정리가 필요하면 파일을 읽는 Claude 스킬이 합니다. 앱은 적고 보여 주는 일만 합니다.
3. **데이터는 평범한 파일입니다.** 앱이 고장 나도 `memos.json`을 열어 볼 수 있고, 특정 서비스에 묶이지 않습니다.
4. **저장은 신중하게.** 파일을 잃는 것이 가장 큰 사고라서, 쓰기보다 검증을 앞세웁니다.

## 데이터 형식

```json
{"memos":[{"id":"mvt6k4e5e46hv","date":"2026-10-07","text":"메모 내용","task":false,"done":false,"updated":"2026-10-29T06:46:38.141Z"}]}
```

| 필드 | 설명 |
|---|---|
| `id` | 메모 고유 키. 수정해도 유지됩니다. 새 메모는 시각(36진수) + 임의 영숫자 6자 |
| `date` | `YYYY-MM-DD` |
| `text` | 메모 한 줄 |
| `task`, `done` | 예전 할 일 표시의 흔적입니다. 지금은 항상 `false`입니다. 호환을 위해 필드는 남겨 둡니다. |
| `updated` | 마지막 수정 시각(UTC ISO). 바뀐 항목만 갱신합니다. |

- 같은 날짜 안의 **배열 순서가 화면 표시 순서**입니다.
- 한 줄 압축 JSON, UTF-8(BOM 없음)으로 저장합니다.

## 저장과 백업

- **원자적 저장:** 임시 파일에 쓰고, 읽어서 검증한 뒤 `File.Replace`로 교체합니다. 저장 도중 꺼져도 원본이 남습니다.
- **불러오기 검증:** 파일이 깨졌거나 비어 있으면 덮어쓰지 않고 멈춥니다.
- **자동 백업:** 같은 폴더의 `backup\`에 시점별 사본을 쌓습니다.

## 동기화

파일 감시 대신 파일 시간표(stamp)를 주기적으로 확인하고, 바뀌었으면 다시 읽습니다. OneDrive가 다른 기기의 변경을 내려받으면 앱이 알아서 반영하고, 트레이 툴팁에 마지막 갱신 시각이 표시됩니다.

앱과 Claude가 거의 동시에 같은 파일을 고치면 한쪽이 덮일 수 있습니다. 백업이 그 위험을 줄이지만 잠금은 없습니다. 혼자 쓰는 것을 전제로 합니다.

## 자체 점검

앱은 명령줄 옵션으로 화면과 저장 로직을 점검할 수 있습니다.

| 옵션 | 동작 |
|---|---|
| `--shot <png> [yyyy-MM]` | 창을 화면 밖에서 그려 PNG로 저장 |
| `--selftest-save <report.txt> <임시폴더>` | 임시 폴더에서 저장 로직(id 유지)을 점검 |
| `--selftest-copy <png>` | 달력 그림을 클립보드로 복사한 뒤 다시 읽어 PNG로 저장 |
